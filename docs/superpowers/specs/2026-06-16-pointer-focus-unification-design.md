# Design: unify pointer + focus hit-testing on one authority

Date: 2026-06-16. Branch: `revert-34-host-first-hittest` (the #34 revert is the
base; this fix lands on top, single PR). HW target: silence (GhostBSD/Linux +
cinnamon + wezterm/gkrellm).

## Problem

Cinnamon sloppy mouse-focus is unreliable on yserver: hovering a window often
fails to focus it (worst on wezterm). The root cause is **two pointer
hit-tests over two trees, consulted by different subsystems**, which disagree
on the Composite Overlay Window (`0x103`) and cinnamon's stage (`0xb00011`):

| Subsystem | Hit-test | Store | keying |
|---|---|---|---|
| Click `target` (`pointer_fanout.rs:249`) | core `root_pointer_target_at` | `ServerState.shape_windows` | `ResourceId` |
| Crossings/focus (`backend.rs:5171` `dispatch_motion_event`) | backend `window_under_cursor` | `KmsCore.shape_input` | host `u32` |

### Confirmed divergence (evidence)

The backend store cannot represent an **empty input region**.
`mirror_shape_to_host_state` → `backend.set_shape_rectangles` does
`if rects.is_empty() { dst.remove(host) }` (`backend.rs:15045`). An absent
entry makes `cursor_inside_shape` return `true` (opaque). The core store keeps
`input = Some([])`, which `window_input_contains` correctly treats as
click-through.

From the captured yserver xtrace (`cinnamon.xtrace`): cinnamon creates region
`0x00f00011` **empty** (`rectangles=;`) and applies it to *both* the stage and
the COW input shapes — the normal "pass clicks through to apps" state. Result:

- **Core**: COW/stage = click-through (correct). Clicks (`target`) work.
- **Backend**: COW/stage = opaque (wrong). `window_under_cursor` returns the
  COW/stage subtree, so the `Enter` generated by `dispatch_motion_event` lands
  on cinnamon's stage instead of the app frame. muffin never sees the `Enter`
  on the app → **sloppy focus silently fails**.

This is precisely the revert-branch symptom ("clicks work, focus unreliable").
It also explains why both prior fixes failed: **#34** (clicks host-first) and
**`fix/unified-pointer-sprite`** (focus host-first) each pushed an authority
toward the *backend*. Xorg uses a single sprite trace over its one window
tree for both pointer and keyboard; the correct direction is the opposite —
everything resolves through the **core resource tree**.

## Goal

One input-shape store, one hit-test — the core resource-tree miSpriteTrace
walk that already honors `None`(opaque) / empty(click-through) — used for
clicks, crossings, motion, and PointerRoot key focus. The backend's parallel
input authority is removed.

Non-goal (separate, pre-existing): recomputing the sprite on map/restack under
a stationary pointer (Xorg's `WindowsRestructured` path; see
`project_yserver_cursor_focus_bugs`). Out of scope for this PR.

## Design

The core hit-test (`ServerState::root_pointer_target_at` → the
`hit_test_children` / `window_input_contains` walk over `resources` +
`shape_windows`) becomes the **single** pointer authority. `target` (clicks)
already uses it on this branch; we route the crossing/motion path through it
too and delete the backend's competing authority.

### 1. Route crossings + motion through the core hit-test (KMS v2 backend)

Add a helper on the v2 backend:

```
fn core_pointer_target_host_xid(&self, state: &ServerState) -> Option<u32>
```

It calls `state.root_pointer_target_at(cursor_x, cursor_y)` (cursor in
root/fb coords, same space the existing backend hit-test uses), takes the
resolved deepest `ResourceId`, and maps it to its `host_xid` via
`state.resources.window(id).host_xid`. Both top-levels and sub-windows are
registered in `xid_map` (`register_top_level` @10012, `register_subwindow`
@10035), so the `ResourceId → host_xid` round-trip is total for mapped
windows.

`dispatch_motion_event` (`backend.rs:5171`) and `process_pointer_button`
(`backend.rs:5253`) replace:

```
let host_xid = self.window_under_cursor().unwrap_or(self.core.window_id);
```

with the core-derived resolution (same `unwrap_or` root-container fallback).
Everything downstream is unchanged: `update_pointer_window` already converts
host→`ResourceId` (`resolve_host_to_nested`, @5102), computes crossings in
`ResourceId` space (`normal_mode_crossings`), and re-derives host xids at
`emit_crossing`. We are only feeding it the *correct* window.

### 2. Delete the backend input authority

Once nothing reads it:

- Remove `window_under_cursor` (`backend.rs:4910`) and `cursor_inside_shape`
  (`backend.rs:5004`) plus their unit tests.
- Remove `KmsCore.shape_input` (`core.rs:1574`), its initializers, and the
  `kind == 2` arm of `set_shape_rectangles` (`backend.rs:15039`).
- Drop `KIND_INPUT` from `mirror_shape_to_host_state` (the mirror existed only
  to feed the backend hit-test). Continue mirroring `Bounding`/`Clip` — those
  feed the renderer (`scene.rs:2395`, `backend.rs:2327`) and stay.

`ServerState.shape_windows` is then the only input-shape store.

### Scope boundary

- **KMS v2 backend only.** The `host_x11`/ynest backend gets `host_xid` from
  the real host X server (which does its own correct hit-test and honors empty
  regions via the host's SHAPE/XFIXES), so its path is already single-authority
  against the host. Do not touch it.

## Risks

- **Sub-window `host_xid` gaps.** If a mapped sub-window lacked a `host_xid`,
  the mapping would fall back to an ancestor and crossings would target too
  shallow. Mitigation: `register_subwindow` populates `xid_map`, so this should
  not occur for mapped windows; HW verification covers it.
- **Non-obvious consumers of the input path.** Two prior fixes built green but
  failed on HW with no clicks. This change is the *inverse* direction (core-
  first, matching Xorg), but the lesson holds: **HW observation gates the
  commit** — no merge before silence confirms.
- **Coordinate space.** `cursor_x/cursor_y` (backend, fb/root space) must match
  `root_pointer_target_at`'s expected root coords. Verify equality with a unit
  test and the existing trace.

## Testing

- **Unit:** a hit-test test proving an empty input region on a parent makes it
  click-through (pointer descends to the sibling beneath), mirroring the
  cinnamon COW/stage case, asserted through the core walk now used by both
  paths. Port the intent of the deleted `window_under_cursor_*` tests onto the
  core hit-test where coverage is lost.
- **Build/clippy/test:** `cargo +nightly fmt`, `cargo clippy`, `cargo test`
  (core + yserver) all green.
- **HW (gating):** on silence, cinnamon + wezterm and gkrellm. Confirm sloppy
  focus follows the pointer reliably (wezterm especially), clicks land on the
  hovered window, and gkrellm buttons respond. Capture a yserver trace
  (`...pointer=trace,...pointer_fanout=debug`); the matching Xorg behavior is
  the reference.
